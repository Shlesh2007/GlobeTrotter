# Traveloop — Conference Presentation Guide
## "I don't know this project — explain everything"

---

## WHAT IS THIS PROJECT IN ONE SENTENCE?

**Traveloop** is a website where users sign up, plan trips, build day-by-day itineraries,
track budgets, manage packing lists, take notes, and browse/book curated travel packages.
It is built with Python (Django) on the backend and Tailwind CSS on the frontend.

---

## THE BIG PICTURE — HOW A DJANGO PROJECT WORKS

Before diving into files, understand this pattern:

```
Browser Request
     ↓
urls.py  ← decides which view handles the request
     ↓
views.py ← fetches data from DB using models, passes to template
     ↓
models.py ← the database tables
     ↓
templates/*.html ← the HTML sent back to the browser
```

Everything else (forms, admin, settings) supports this core loop.

### `manage.py`
**What it is:** The Django command-line tool.
**What it does:** You run almost every admin task through this.
**How to explain it:** "This is the remote control for the project. Want to start the server?
`python manage.py runserver`. Want to update the database? `python manage.py migrate`.
Want to create an admin login? `python manage.py createsuperuser`.
You never edit this file — Django generates it automatically."

---

### `requirements.txt`
**What it is:** A list of Python packages this project needs.
**Contents:**
- `Django==5.0.14` — the web framework
- `Pillow==12.2.0` — handles image uploads (profile pics, trip covers)
- `whitenoise==6.12.0` — serves CSS/JS files efficiently in production

**How to explain it:** "Like a shopping list. When someone new clones the project,
they run `pip install -r requirements.txt` and get everything they need."

### `package.json`
**What it is:** Node.js dependency list (for the CSS build tool only).
**Contents:** Tailwind CSS, PostCSS, Autoprefixer — all dev tools, not production dependencies.
**How to explain it:** "The project uses Tailwind CSS for styling. Tailwind needs Node.js
to compile. This file tells Node which tools to install. It has nothing to do with
running the Django app itself."

---

### `package-lock.json`
**What it is:** Auto-generated exact version lock for Node packages.
**How to explain it:** "Auto-generated by npm. You never edit it. It ensures every

### `tailwind.config.js`
**What it is:** Configuration for Tailwind CSS.
**What it does:** Tells Tailwind which files to scan for CSS class names so it only

## SECTION 2 — THE `traveloop/` FOLDER (Project Configuration)

This folder is the **Django project container**. It holds settings and the top-level URL
configuration. It does NOT contain any of the actual app logic.

---

### `traveloop/settings.py`
**What it is:** The master configuration file for the entire Django project.
**Key things it controls:**
- `DEBUG` — `True` in development (shows error pages), `False` in production
- `SECRET_KEY` — a long random string Django uses for security (kept in environment variables)
- `INSTALLED_APPS` — the list of apps Django loads (includes the `travel` app)
- `DATABASES` — SQLite locally, PostgreSQL on Render (switches automatically)
- `TEMPLATES` — tells Django where to find HTML files (`templates/` folder)
- `STATIC_URL / STATIC_ROOT` — where CSS/JS files live
- `MEDIA_URL / MEDIA_ROOT` — where uploaded files (images) are stored
- `LOGIN_URL` — what URL to redirect to when a user isn't logged in
- `EMAIL_*` settings — Gmail SMTP for password reset emails

**How to explain it:** "This is the brain of the project. Every major behavior —
database choice, which apps are active, where files are stored, email setup —
is controlled from here."

---

### `traveloop/urls.py`
**What it is:** The ROOT URL router. The very first file Django checks when any
request comes in.
**What it does:**
- `/admin/` → Django admin panel
- `/accounts/` → login, signup, password reset (from `travel/auth_urls.py`)
- Everything else → the main app URLs (from `travel/urls.py`)

**How to explain it:** "Think of it as a receptionist. Every incoming web request
passes through here first, and it gets directed to the right department."

---

### `traveloop/wsgi.py`
**What it is:** WSGI (Web Server Gateway Interface) entry point.
**How to explain it:** "When Gunicorn (the production web server) starts, it uses this
file as the entry point to load the Django app. You never edit it."

---

### `traveloop/asgi.py`
**What it is:** ASGI entry point (for async support).
**How to explain it:** "Similar to wsgi.py but for asynchronous servers. Not actively
used in this project but included by Django's default setup."

---

### `traveloop/__init__.py`
**What it is:** Makes this folder a Python package.
**How to explain it:** "An empty file that just tells Python 'this folder is a module'.
Ignore it."

### `travel/models.py` ⭐ MOST IMPORTANT FILE
**What it is:** Defines all the database tables as Python classes.
**How to explain it:** "If the database is a spreadsheet, this file defines the
column headers for every sheet. Each class = one table."

**Every model (table) explained:**

| Model | Real-world meaning | Key fields |
|---|---|---|
| `UserProfile` | Extra info about a registered user | avatar, phone, bio, travel style |
| `Trip` | A user's trip plan | title, dates, cover image, public/private toggle |
| `CityStop` | One city within a trip | city name, country, arrival/departure dates, order |
| `Activity` | Something to do in a city | title, category, cost in INR, duration, date |
| `Budget` | The money plan for a trip | transport, hotel, food, activity, misc costs |
| `PackingItem` | One item on the packing list | item name, category, packed yes/no |
| `Note` | A freeform note for a trip | title, content |
| `Destination` | A curated travel destination shown publicly | name, country, description, image |
| `Package` | A bookable travel package | name, price per person, duration, max travelers |
| `Booking` | A user's package booking record | user, package, date, price, status |
| `Testimonial` | Customer review shown on homepage | name, quote, star rating |
| `NewsletterSubscriber` | Email subscriber | email, active yes/no |

**Relationship summary:**
- One `User` → many `Trips`
- One `Trip` → many `CityStops`, one `Budget`, many `PackingItems`, many `Notes`
- One `CityStop` → many `Activities`
- One `Destination` → many `Packages`
- One `User` → many `Bookings`

## SECTION 11 — HOW ALL THE FILES CONNECT (Data Flow Example)

### Example: User visits `/trips/3/budget/`

```
1. Browser sends GET request to /trips/3/budget/

2. traveloop/urls.py
   → sees it starts with nothing special
   → passes to travel/urls.py

3. travel/urls.py
   → matches pattern: trips/<int:trip_id>/budget/
   → calls views.budget_breakdown(request, trip_id=3)

4. travel/views.py → budget_breakdown()
   → queries travel/models.py: Budget.objects.get_or_create(trip_id=3)
   → builds chart_data dict with the 5 cost categories
   → passes trip, form, budget, chart_data to template

5. templates/travel/budget_breakdown.html
   → extends templates/base.html
   → base.html includes includes/navbar.html, includes/sidebar.html
   → budget.html renders the BudgetForm and passes chart_data to static/js/budget.js
   → budget.js draws the chart in the browser

6. Browser displays the budget page
```

## SECTION 14 — COMMON QUESTIONS YOU MIGHT BE ASKED

**Q: Why Django and not Flask or FastAPI?**
A: Django includes everything out of the box — ORM, admin panel, auth, forms,
migrations. For a feature-rich app like this, Django's batteries-included approach
is faster than assembling Flask microservices.

**Q: Why SQLite in development?**
A: Zero setup, single file, works instantly. For production we switch to PostgreSQL
automatically via the DATABASE_URL environment variable.

**Q: How does public sharing work?**
A: Each trip has a `public_slug` field which is a UUID4 — a random 32-character string.
When the user makes a trip public, that UUID becomes the shareable link.
It's unguessable and doesn't expose the numeric trip ID.

**Q: How is authentication handled?**
A: Django's built-in auth system. Users register with email (stored as username),
password is hashed automatically by Django. Password resets use Gmail SMTP.
Session-based authentication — no tokens or JWTs.

**Q: How does Tailwind CSS work here?**
A: Tailwind is a utility-first CSS framework. We write HTML classes like
`class="bg-blue-500 p-4 rounded"` instead of writing custom CSS.
The Tailwind CLI scans our templates, finds all used classes,
and compiles only those into a small CSS file.

**Q: Where are uploaded images stored?**
A: Locally in the `media/` folder. In production on Render, the filesystem
is ephemeral (resets on redeploy). For permanent storage you'd add S3 or Cloudinary.
